# 前端工程文档

## 1. 项目概述

前端工程位于 `frontEnd/`，是 AI 试戴间的 Web 客户端。它提供移动端优先的虚拟试戴操作界面，用户可以：

- 选择或上传手绳/手链图片。
- 选择或上传模特/手腕图片。
- 发起 AI 试戴生成任务。
- 轮询任务状态并展示生成结果。

当前 UI 主要聚焦“手绳/手链 + 手腕模特”的两步生成流程。代码中仍保留了场景面板组件，但主应用当前没有接入场景选择步骤。

## 2. 技术栈

- 构建工具：Vite 6
- 前端框架：React 19
- 语言：TypeScript 5.7
- 样式：Tailwind CSS 4 + `tw-animate-css`
- UI 组件：shadcn/ui 风格组件 + Radix UI
- 图标：lucide-react
- 表单相关依赖：react-hook-form、zod、@hookform/resolvers
- 主题依赖：next-themes
- 通知：本地 `use-toast` / Toaster 组件
- 包管理：npm

## 5. Vite 配置

配置文件：`frontEnd/vite.config.ts`

主要配置：

- React 插件：`@vitejs/plugin-react`
- 路径别名：`@` → `frontEnd/src`
- 本地开发代理：
  - `/api` → `http://localhost:8000`
  - `/uploads` → `http://localhost:8000`
  - `/results` → `http://localhost:8000`

因此前端开发环境可以直接请求 `/api/...`，由 Vite 转发到后端 FastAPI 服务。

## 6. TypeScript 配置

配置文件：`frontEnd/tsconfig.json`

关键选项：

- `strict: true`：启用严格类型检查。
- `noUnusedLocals: true`：禁止未使用局部变量。
- `noUnusedParameters: true`：禁止未使用参数。
- `moduleResolution: bundler`：适配 Vite/bundler 模块解析。
- `jsx: react-jsx`：使用 React 新 JSX 转换。
- `paths`：`@/*` 指向 `./src/*`。

## 9. 状态管理

当前没有使用全局状态库，业务状态集中在 `src/App.tsx` 中通过 React Hooks 管理。

主要状态：

| 状态 | 类型 | 说明 |
| --- | --- | --- |
| `accessoryPanelOpen` | boolean | 配饰抽屉是否打开 |
| `modelPanelOpen` | boolean | 模特抽屉是否打开 |
| `selectedAccessoryType` | `AccessoryType` | 当前配饰类型，目前只有 `bracelet` |
| `selectedAccessory` | `AccessorySelection \| null` | 当前配饰选择 |
| `selectedModel` | `ModelSelection \| null` | 当前模特选择 |
| `isLoading` | boolean | 是否正在生成 |
| `generatedImage` | `string \| null` | 生成结果图片 URL |
| `pollIntervalRef` | `useRef` | 任务状态轮询定时器 |

完成条件：

```ts
const isAllCompleted = !!selectedAccessory && !!selectedModel
```

当配饰和模特都已选择时，底部按钮可点击。

## 10. 核心业务流程

### 10.1 选择配饰

组件：`src/components/step-panels/accessory-panel.tsx`

功能：

1. 打开抽屉后请求后端预设配饰：
   - `GET /api/presets/accessories?type=bracelet`
2. 展示配饰类型，目前只有手绳/手链。
3. 支持上传图片：
   - `POST /api/upload?type=accessory`
4. 用户选择预设或上传图片后点击确认。
5. 回传到 `App` 中更新 `selectedAccessory`。

当前确认逻辑只向 `App` 回传图片 URL 和类型，没有回传预设 ID，因此 `App` 会把它组装为：

```ts
{
  source: 'preset',
  url: imageUrl
}
```

### 10.2 选择模特

组件：`src/components/step-panels/model-panel.tsx`

功能：

1. 打开抽屉后请求后端预设模特：
   - `GET /api/presets/models?category=wrist`
2. 展示模特分类，目前只有手腕。
3. 支持上传图片：
   - `POST /api/upload?type=model`
4. 用户选择预设或上传图片后点击确认。
5. 回传到 `App` 中更新 `selectedModel`。

当前确认逻辑只回传图片 URL，没有回传预设 ID，因此 `App` 会把它组装为：

```ts
{
  source: 'preset',
  url: imageUrl
}
```

### 10.3 创建生成任务

触发组件：`src/components/bottom-action-bar.tsx`

触发函数：`App.handleGenerate()`

请求：

```ts
createGeneration({
  accessory_type: selectedAccessoryType,
  accessory: selectedAccessory,
  model: selectedModel,
})
```

对应后端接口：

```http
POST /api/generate
```

### 10.4 轮询生成状态

创建任务成功后，前端每 1500ms 调用：

```http
GET /api/generate/{task_id}
```

轮询规则：

- `completed`：设置 `generatedImage`，停止 loading，弹出成功提示。
- `failed`：停止 loading，弹出失败提示。
- `pending` / `processing`：继续轮询。
- 最多轮询 80 次，大约 2 分钟，超时后提示失败。

组件卸载时会清理轮询定时器。

## 11. API 封装

文件：`src/services/api.ts`

封装函数：

| 函数 | 方法和路径 | 说明 |
| --- | --- | --- |
| `getPresetAccessories(type?)` | `GET /api/presets/accessories` | 获取配饰预设 |
| `getPresetModels(category?)` | `GET /api/presets/models` | 获取模特预设 |
| `getPresetScenes(category?)` | `GET /api/presets/scenes` | 获取场景预设 |
| `uploadImage(file, type)` | `POST /api/upload?type=...` | 上传图片 |
| `createGeneration(request)` | `POST /api/generate` | 创建 AI 生成任务 |
| `getTaskStatus(taskId)` | `GET /api/generate/{taskId}` | 查询任务状态 |

`handleResponse<T>()` 会：

- 解析 JSON。
- HTTP 非 2xx 时抛出错误。
- 响应中 `success === false` 时抛出错误。
- 优先从 `error`、`message`、`detail` 中提取错误信息。

## 15. 与后端集成

前端依赖后端提供以下能力：

1. 预设资源：
   - `/api/presets/accessories`
   - `/api/presets/models`
   - `/api/presets/scenes`
2. 文件上传：
   - `/api/upload`
3. 生成任务：
   - `/api/generate`
   - `/api/generate/{task_id}`
4. 静态资源：
   - `/uploads/...`
   - `/results/...`

本地开发推荐同时启动：

```bash
# 终端 1
cd backEnd
uvicorn main:app --reload --host 0.0.0.0 --port 8000

# 终端 2
cd frontEnd
npm run dev
```
