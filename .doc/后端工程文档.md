# 后端工程文档

## 1. 项目概述

后端工程位于 `backEnd/`，是 AI 试戴间的服务端应用，负责：

- 提供预设配饰、模特、场景资源接口。
- 接收用户上传的配饰图、模特图、遮罩图等图片文件。
- 创建 AI 生成任务，并提供任务状态查询接口。
- 根据配置选择 Mock、本地 Stable Diffusion 或阿里百炼作为图像生成服务。
- 使用 SQLite 持久化预设数据和生成任务数据。
- 提供上传文件、生成结果和预设静态资源的静态访问路径。

当前应用主题偏向“手绳/手链虚拟试戴”，但模型和提示词基类中预留了项链、耳饰、戒指等配饰类型描述。

## 2. 技术栈

- Web 框架：FastAPI
- ASGI 服务：Uvicorn
- 数据库 ORM：SQLAlchemy 2.x
- 数据库：SQLite
- 配置管理：pydantic-settings + `.env`
- 文件上传：python-multipart
- 图像处理：Pillow
- 限流：slowapi + limits
- HTTP 请求：requests
- AI 服务：
  - MockAIService：本地开发调试
  - StableDiffusionAIService：本地 Stable Diffusion WebUI API
  - BailianAIService：阿里百炼 DashScope Qwen-Image-2.0-Pro

## 4. 启动流程

### 4.1 安装依赖

```bash
cd backEnd
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Windows PowerShell 可使用：

```powershell
cd backEnd
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 4.2 配置环境变量

复制环境变量示例：

```bash
cp .env.example .env
```

默认可使用 `AI_PROVIDER=mock` 启动，无需外部 AI 服务。

### 4.3 启动服务

```bash
cd backEnd
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

或直接运行：

```bash
python main.py
```

启动后：

- API 文档：`/docs`
- 根路径：`/`
- 上传资源：`/uploads/...`
- 生成结果：`/results/...`
- 预设静态资源：`/static/...`

## 6. 应用入口与中间件

入口文件：`backEnd/main.py`

主要职责：

- 创建 FastAPI 应用，标题来自配置。
- 注册 SlowAPI 限流异常处理。
- 配置 CORS。
- 创建上传、结果和静态资源目录。
- 挂载静态目录：
  - `/uploads` → `UPLOAD_DIR`
  - `/results` → `RESULT_DIR`
  - `/static` → `STATIC_DIR`
- 注册 API 路由：
  - `/api/presets`
  - `/api/upload`
  - `/api/generate`
- 启动事件中初始化数据库、重置卡住的任务、写入默认预设数据。

## 8. API 接口

所有业务接口统一挂载在 `/api` 前缀下，响应模型一般为：

```json
{
  "success": true,
  "data": {},
  "message": null
}
```

### 8.1 查询配饰预设

```http
GET /api/presets/accessories?type=bracelet
```

参数：

- `type`：可选，配饰类型，目前前端只使用 `bracelet`。

返回数据项：

```json
{
  "id": "bracelet_001",
  "type": "bracelet",
  "name": "经典珍珠手链",
  "image_url": "..."
}
```

### 8.2 查询模特预设

```http
GET /api/presets/models?category=wrist
```

参数：

- `category`：可选，模特分类；传 `all` 时不筛选。

### 8.3 查询场景预设

```http
GET /api/presets/scenes?category=studio
```

参数：

- `category`：可选，场景分类。

### 8.4 上传图片

```http
POST /api/upload?type=accessory
Content-Type: multipart/form-data
```

表单字段：

- `file`：图片文件。
- `type`：上传类型，如 `accessory` / `model` / `mask`。

返回：

```json
{
  "success": true,
  "data": {
    "file_id": "accessory_xxxxxxxxxxxx",
    "url": "/uploads/accessory_xxxxxxxxxxxx.jpg",
    "thumbnail_url": "/uploads/accessory_xxxxxxxxxxxx_thumb.jpg"
  }
}
```

上传服务会检查 `content_type` 是否以 `image/` 开头，并尝试生成 200x200 缩略图。

### 8.5 创建生成任务

```http
POST /api/generate
Content-Type: application/json
```

请求体：

```json
{
  "accessory_type": "bracelet",
  "accessory": {
    "source": "preset",
    "id": "bracelet_001",
    "url": "/uploads/accessory.jpg"
  },
  "model": {
    "source": "preset",
    "id": "wrist_001",
    "url": "/uploads/model.jpg",
    "mask_url": "/uploads/mask.png"
  },
  "scene": {
    "id": "scene_studio"
  },
  "options": {
    "lighting": "natural",
    "prompt": "用户补充要求",
    "strength": 0.75,
    "guidance_scale": 7.5
  }
}
```

返回：

```json
{
  "success": true,
  "data": {
    "task_id": "task_xxxxxxxxxxxxxxxx",
    "status": "pending"
  }
}
```

该接口受到 SlowAPI 限流配置影响。

### 8.6 查询任务状态

```http
GET /api/generate/{task_id}
```

返回：

```json
{
  "success": true,
  "data": {
    "task_id": "task_xxxxxxxxxxxxxxxx",
    "status": "processing",
    "progress": 70,
    "result_url": null,
    "error": null
  }
}
```

状态：

- `pending`：等待处理
- `processing`：处理中
- `completed`：完成，`result_url` 有值
- `failed`：失败，`error` 有值
- `not_found`：内存队列中找不到该任务

## 9. 生成任务流程

任务队列实现位于 `app/services/task_queue.py`。

流程：

1. 前端调用 `POST /api/generate`。
2. 后端创建 `GenerationTask` 数据库记录。
3. 后端把任务写入内存字典 `self.tasks`。
4. 后台守护线程每秒扫描 pending 任务。
5. 任务进入 processing：
   - 查询预设配饰，得到配饰名称和图片。
   - 查询预设场景，得到场景提示词模板。
   - 构建 AI 生成提示词。
   - 查询预设模特，得到模特图片。
   - 调用当前 AI 服务生成图片。
   - 保存结果到 `RESULT_DIR`。
   - 更新数据库任务状态和内存状态。
6. 前端轮询 `GET /api/generate/{task_id}` 获得结果。

注意：当前任务状态查询主要依赖内存队列；服务重启后，数据库中的 processing 任务会被置为 failed，但已经完成或历史任务不一定能通过内存队列查询到。

## 10. AI 服务说明

### 10.1 AI 服务工厂

`app/services/ai/factory.py` 根据 `AI_PROVIDER` 返回不同服务：

- `mock`：返回 `MockAIService`
- `stable_diffusion`：返回 `StableDiffusionAIService`
- `bailian`：返回 `BailianAIService`

### 10.2 MockAIService

用于本地开发，无需外部服务。

- 优先返回 `data/placeholder.jpg`。
- 如果占位图不存在，则动态创建一张 512x640 的 JPEG 图片。

### 10.3 StableDiffusionAIService

调用本地 Stable Diffusion WebUI 的 img2img 接口：

```text
POST {STABLE_DIFFUSION_API_URL}/sdapi/v1/img2img
```

主要参数：

- `init_images`
- `prompt`
- `negative_prompt`
- `denoising_strength`
- `cfg_scale`
- `width=512`
- `height=640`
- `sampler_name=Euler a`
- `steps=20`

### 10.4 BailianAIService

调用阿里百炼 DashScope `ImageGeneration.call`，默认模型为 `qwen-image-2.0-pro`。

处理逻辑：

- 下载模特图和配饰图。
- 使用 Pillow 处理 EXIF 方向和图片格式。
- 校验图片尺寸需在 240 到 8000 像素之间。
- 转换为 `data:{MIME_type};base64,{base64_data}`。
- 调用百炼图像生成接口。
- 从响应中提取结果图片 URL。
- 下载结果图片并返回二进制数据。

使用百炼时必须配置：

```env
AI_PROVIDER=bailian
BAILIAN_API_KEY=你的 API Key
BAILIAN_MODEL=qwen-image-2.0-pro
```

## 11. 初始化数据

启动时调用 `init_data.ensure_initial_data()`，会先确保 `STATIC_DIR/presets/` 下存在默认预设 PNG 图片，并按固定 ID 同步写入默认数据：

- 配饰：2 个手链/手绳占位预设，图片路径为 `/static/presets/bracelet_*.png`。
- 模特：2 个手腕占位预设，图片路径为 `/static/presets/wrist_*.png`。
- 场景：摄影棚和自然户外两个场景，图片路径为 `/static/presets/scene_*.png`。

默认预设数据会按 ID upsert，已有记录会同步更新为当前初始化配置。

## 12. 与前端集成

前端 Vite 开发服务器会代理：

- `/api` → `http://localhost:8000`
- `/uploads` → `http://localhost:8000`
- `/results` → `http://localhost:8000`
- `/static` → `http://localhost:8000`

因此本地开发时：

1. 后端运行在 `localhost:8000`。
2. 前端运行在 `localhost:5173`。
3. 前端通过同源路径 `/api/...` 访问后端。

## 13. 当前注意事项

- `app/dependencies.py` 中使用了 `Request` 类型，但当前文件未导入 `Request`。
- `MAX_UPLOAD_SIZE` 已配置，但 `StorageService.save_upload()` 当前未校验文件大小。
- 上传文件扩展名来自原始文件名，建议后续增加白名单和 MIME/内容校验。
- `RATE_LIMIT_ENABLED=false` 不会移除 `generate.py` 上已经注册的限流装饰器。
- `TaskQueue` 使用内存字典保存运行态任务，服务重启后无法恢复内存任务状态。
- 任务队列当前是单进程内线程模型，多 worker 部署时任务状态和执行可能不一致。
- `accessory_source` / `model_source` 传 `preset` 时，如果前端只传 URL 不传 ID，后端会使用 URL，但预设名称会退回默认值。
- `mask_service.py` 当前提供遮罩生成能力，但主生成流程尚未使用 `model_mask_url`。
